# Documentation

Everything this site publishes, in the order worth reading it. Each entry says
what the page answers, so you can tell in one line whether it is the one you
need.

If you are new, read [how it works](/about/how-it-works) first. It explains
where the data comes from, which is the question every other page answers
differently.

---

## Understanding the catalogue

- **[How it works](/about/how-it-works)** — where a fact about a plugin comes
  from, what happens to it, how search works, and what this catalogue will not
  claim to do.
- **[Plugin formats](/about/formats)** — the eight plugin formats here: what
  each is, which hosts load it, and an introduction to Jig, the web plugin
  format you fetch rather than install.
- **[Measurements](/about/measurements)** — what the profiler measures, what
  each verdict means, and why a reading is about one binary on one machine.
- **[Plugin profiles](/about/profiles)** — what a plugin profile is, and why it
  is worth an author filling one in.

## Reading the catalogue

- **[Search](/)** — the front page, and the whole catalogue.
- **[All plugins](/plugins)** — everything, a page at a time, filterable by
  format, category, role, vendor, platform, price and licence.
- **[Services](/services)** — every way to read the data: web pages, a JSON
  API, RDF, a package registry view, an agent endpoint. Start here if you want
  the data rather than the site.
- **[The SPARQL endpoint](/about/sparql)** — a read-only public endpoint for
  asking a question the pages do not answer.
- **[The MCP endpoint](/about/mcp)** — the same catalogue as tools an AI agent
  can call.
- **[Datasets](/dumps/)** — the whole catalogue as files, rebuilt nightly,
  split by licence so you always know what you are taking.
- **[Vocabularies](/ns)** — the RDF terms every published description uses, as
  documents that resolve.
